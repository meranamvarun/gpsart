## Acceptance evidence

1. Save, list, rename, reopen, delete, and offline GPX export are covered by `tests/saved-routes.test.ts`. They operate without account state.
2. Offline reopening hydrates route details from the stored request and immutable candidate snapshot, clears unrelated job-attempt state, and performs no server or routing call.
3. Saved-route and account copy consistently says “Saved on this device,” explains that clearing site data removes saves, and states that sign-in does not upload, erase, or relabel them.
4. Rename and delete use one-record read-write transactions. Injected write failures leave the target and unrelated records intact.
5. Tests inject browser-storage denial, quota exhaustion, malformed records, and unknown schema versions. Record failures are isolated, while save failures leave the selected server snapshot and its existing GPX action untouched.
6. The stored schema contains no account identity or sync operation. Repeated lists before and after an external authentication-state change are identical.

No route geometry, distance, access, instructions, or success data is generated by the storage layer. The repository accepts only the strict TS-205 snapshot decoder and preserves the exact stored traversal for the TS-207 offline exporter.
